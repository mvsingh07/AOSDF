# Single-review policy reference

The canonical framework now defines single implementation review in C16 and outcome-first delivery in C17. See [current workflow rules](../../reference/current-workflow-rules.md). Earlier installations adopt the current policy through their own reviewed migration; no active project's policy changes just because the reusable root was updated.

At most one review per task during implementation. High-risk remains independent and coordinator-arranged; earlier reviews count. Fix acceptance-path blockers and validate without a focused/post/re-review cycle. Additional review requires an explicit founder request. Tests, administrative acceptance and all protected-operation approvals remain required.
