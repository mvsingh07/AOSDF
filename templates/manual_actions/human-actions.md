# Human actions: learn, read, review, research, answer

Non-blocking learning/research items help the founder follow development. They never block task acceptance. Simple authorizations remain in the founder decision inbox; manual setup remains in project actions. A decision needing research appears here through `ask --research` as well as in decisions.

Outside RUNNING Ultimate Auto, owners post meaningful `automode.py learn --from <role> --kind <learn|read|review|research|answer> --title ... --why ...` items, with a research topic or code/design link as appropriate. The founder uses `learning`, `done`, or `answer`. While Ultimate Auto is RUNNING this learning layer is off for speed; Summary and required task evidence remain.

The relay regenerates only the table between these markers. Instantiate this template with a fresh document identity under project `12_Manual_Actions/`; do not copy another project's items.
