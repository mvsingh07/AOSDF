# AOSDF 3.7.0 — portable automation and existing-owner delivery

This root release adapts the latest registry-selected update4 captures into inactive reusable source. The founder requested adoption on 2026-11-25. The selected architecture is the existing bridge/invoke/trigger flow, consolidated under `automation/`; the historical separate sprint controller is excluded.

New capabilities include explicit fresh-session executor/profile selection, bound existing-owner transport, immutable peer snapshots and read ACKs, bounded continuation/native wake windows, consumed-round reconciliation, owner-wake adapters, `automode` control/console, strict round tags and per-Mode entry scripts. Durable role instructions follow the same policy across entrypoints.

The four default process Modes remain unchanged. Ultimate Auto is an optional existing-owner delivery extension. The source product's environment-specific policy and single-review override are not universal defaults; the latter is an inactive example only. The generic supervisor retains its previous disabled real-dispatch boundary and does not import private pilot permissions.

The delivery/wake transport is currently qualified against three reference threads. Its CLI/session adapters require installation-specific acceptance. No runtime, wake, account, project migration, deployment or publication is activated by this release.

Use [the migration recipe](migrate.md), [adaptation manifest](source-adaptations.json) and [source inventory](inventory.json). Earlier release inventories remain historical snapshots; run the top-level inventory checker against the current registry.
